# Посібник з Role-Based Access Control (RBAC)

## Огляд системи

Система підтримує три типи користувачів з різними рівнями доступу:

### 1. **Адміністратор (ROLE_ADMIN)**
Email: `admin@example.com`

**Доступні функції:**
- ✅ Керування працівниками (додавання, редагування, звільнення)
- ✅ Керування книгами (додавання, редагування, видалення)
- ✅ Перегляд і обробка всіх замовлень
- ✅ Керування клієнтами (блокування/розблокування)
- ✅ Повний доступ до всіх функцій системи

**Меню навігації:**
- Каталог
- Працівники
- Книги
- Замовлення
- Клієнти

---

### 2. **Працівник (ROLE_EMPLOYEE)**
Email: `employee@example.com`

**Доступні функції:**
- ✅ Керування книгами (додавання, редагування, видалення)
- ✅ Перегляд і обробка всіх замовлень
- ✅ Керування клієнтами (блокування/розблокування)
- ❌ НЕ має доступу до керування працівниками

**Меню навігації:**
- Каталог
- Книги
- Замовлення
- Клієнти

**Обмеження:**
- Спроба доступу до `/employees` (прямим посиланням) → 403 Access Denied

---

### 3. **Покупець (ROLE_CUSTOMER)**
Email: `customer@example.com`

**Доступні функції:**
- ✅ Перегляд каталогу книг
- ✅ Додавання книг до кошика
- ✅ Оформлення замовлень
- ✅ Перегляд історії своїх замовлень
- ✅ Редагування профілю
- ❌ НЕ має доступу до адміністративних функцій

**Меню навігації:**
- Каталог
- Мої замовлення
- Кошик (іконка)
- Профіль

---

## Сторінки та права доступу

### Сторінка "Працівники" (`/employees`)
- **Доступ:** Тільки адміністратори
- **Функції:**
  - Таблиця всіх працівників
  - Кнопка "Додати працівника" (+)
  - Кнопки "Редагувати" (олівець) та "Звільнити" (смітник) для кожного запису
  - Відображення статусу працівника (Активний/Звільнений)

### Сторінка "Книги" (`/manage-books`)
- **Доступ:** Працівники та адміністратори
- **Функції:**
  - Перегляд усіх книг в каталозі
  - Кнопка "Додати книгу"
  - Кнопки "Редагувати" та "Видалити" на кожній картці книги
  - Форма додавання/редагування з всіма полями

### Сторінка "Замовлення" (`/all-orders`)
- **Доступ:** Працівники та адміністратори
- **Функції:**
  - Глобальний список усіх замовлень магазину
  - Інформація про клієнта, товари, доставку
  - Кнопки "Підтвердити" та "Скасувати" для замовлень в статусі "pending"
  - Відображення статусів замовлень (В обробці, Підтверджено, Скасовано)

### Сторінка "Клієнти" (`/clients`)
- **Доступ:** Працівники та адміністратори
- **Функції:**
  - Список усіх клієнтів
  - Статистика замовлень для кожного клієнта
  - Кнопка "Заблокувати"/"Розблокувати" клієнта
  - Відображення статусу (Активний/Заблокований)

### Сторінка "Мої замовлення" (`/orders`)
- **Доступ:** Покупці
- **Функції:**
  - Історія замовлень поточного користувача
  - Деталі кожного замовлення
  - Інформація про доставку та оплату

## Інтеграція з Java Backend

Всі сервіси налаштовані на роботу з вашим Java API:

### API Endpoints

**EmployeeService:**
- `GET /api/employees` - отримати всіх працівників
- `GET /api/employees/{id}` - отримати працівника за ID
- `POST /api/employees` - додати нового працівника
- `PUT /api/employees/{id}` - оновити працівника
- `DELETE /api/employees/{id}` - звільнити працівника

**ClientService:**
- `GET /api/clients` - отримати всіх клієнтів
- `GET /api/clients/{id}` - отримати клієнта за ID
- `POST /api/clients/{id}/block` - заблокувати клієнта
- `POST /api/clients/{id}/unblock` - розблокувати клієнта

**OrderService:**
- `GET /api/orders` - отримати всі замовлення
- `GET /api/orders/customer/{email}` - отримати замовлення клієнта
- `POST /api/orders` - створити замовлення
- `POST /api/orders/{id}/confirm` - підтвердити замовлення
- `POST /api/orders/{id}/cancel` - скасувати замовлення

**BookService:**
- `GET /api/books` - отримати всі книги
- `GET /api/books/{id}` - отримати книгу за ID
- `POST /api/books` - додати нову книгу
- `PUT /api/books/{id}` - оновити книгу
- `DELETE /api/books/{id}` - видалити книгу

### Налаштування API URL

За замовчуванням використовується `http://localhost:8080/api`

Для зміни URL встановіть змінну середовища:
```
REACT_APP_API_URL=http://your-backend-url/api
```

### Mock Data

Якщо бекенд недоступний, frontend автоматично використовує mock дані для тестування інтерфейсу.

## Система захисту доступу

### Перевірка на рівні UI
- Header показує тільки доступні пункти меню залежно від ролі
- Компоненти рендеряться тільки для авторизованих ролей

### Перевірка на рівні навігації
- `handleViewChangeWithAuth()` перевіряє права доступу перед зміною view
- Неавторизований доступ → редірект на сторінку "403 Access Denied"

### Приклад захисту:
```typescript
// Спроба працівника зайти на /employees
if (view === 'employees' && !isAdmin) {
  setCurrentView('access-denied'); // 403
  return;
}
```

## Тестування системи

1. **Увійдіть як адміністратор:**
   - Email: `admin@example.com`
   - Перевірте доступ до всіх розділів меню
   - Протестуйте додавання/редагування/видалення працівників

2. **Увійдіть як працівник:**
   - Email: `employee@example.com`
   - Перевірте, що в меню НЕМАЄ пункту "Працівники"
   - Спробуйте вручну перейти на /employees - має показати 403
   - Протестуйте керування книгами, замовленнями, клієнтами

3. **Увійдіть як покупець:**
   - Email: `customer@example.com`
   - Перевірте роботу кошика та оформлення замовлень
   - Переглянути тільки свої замовлення (не всі)

## Структура файлів

```
/services/
  ├── employeeService.ts    # API для роботи з працівниками
  ├── clientService.ts      # API для роботи з клієнтами
  ├── orderService.ts       # API для роботи з замовленнями
  └── bookService.ts        # API для роботи з книгами

/components/
  ├── EmployeesPage.tsx     # Керування працівниками (тільки адмін)
  ├── ClientsPage.tsx       # Список клієнтів (працівники + адміни)
  ├── AllOrdersPage.tsx     # Всі замовлення (працівники + адміни)
  ├── ManageBooksPage.tsx   # Керування книгами (працівники + адміни)
  ├── AccessDenied.tsx      # Сторінка 403
  └── Header.tsx            # Навігація з role-based меню

/contexts/
  └── AuthContext.tsx       # Контекст з isAdmin, isEmployee, isCustomer

/types/
  └── index.ts              # Employee, Client, Order, User types
```

## Наступні кроки

1. **На бекенді (Java):**
   - Реалізуйте всі API endpoints
   - Додайте JWT автентифікацію
   - Налаштуйте CORS для frontend
   - Додайте role-based authorization на рівні endpoints

2. **На frontend:**
   - Додайте токени автентифікації до запитів
   - Реалізуйте refresh token логіку
   - Додайте обробку помилок з бекенду
   - Покращити UX з loading states

---

**Примітка:** Пароль для всіх тестових акаунтів може бути будь-яким (mock автентифікація). У production використовуйте реальну автентифікацію з вашим Java бекендом.
